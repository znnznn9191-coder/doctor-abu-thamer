# خطة التنفيذ

## الهدف
تحويل المشروع الحالي من مُبدئ تجريبي إلى منصة محلية لإدارة الأبحاث الأكاديمية بشكل عملي، مع إمكانية التوسع لاحقاً إلى النشر عبر الإنترنت دون إعادة تصميم شاملة للبنية.

## المبادئ الأساسية
- الاحتفاظ بالهوية البصرية الحالية للواجهة العربية والاتجاه RTL.
- إبقاء جميع الوحدات الداخلية في `backend/agents/` و`backend/services/`.
- عدم عرض أي تفاصيل داخلية في واجهة المستخدم العامة.
- عدم استخدام أي واجهة/مزوّد AI حقيقي في هذه المرحلة.
- توجيه البنية نحو نموذج قابل للاستبدال لاحقاً بمزود خارجي بدون إعادة هيكلة شاملة.

## مراحل التنفيذ

### Phase 0: Safety and Inspection
- فحص هيكل المشروع الحالي.
- توثيق الحالة الحالية.
- عدم حذف أي ملفات عاملة.
- إنشاء مستندات المعمارية الأساسية.

### Phase 1: Backend Foundation
- إنشاء `backend/package.json`.
- إنشاء خادم Express.
- إعداد إعدادات الـ config.
- إنشاء بنية `routes/`, `controllers/`, `services/`, `db/`.
- تثبيت الاعتماديات الأساسية: `express`, `cors`, `better-sqlite3`, `uuid`.
- تهيئة قاعدة SQLite محلية.

### Phase 2: Database Model
- إنشاء الجداول:
  - `researches`
  - `research_sections`
  - `research_sources`
  - `research_history`
- تفعيل `FOREIGN KEY`.
- إنشاء دالة تنفيذية لتهيئة قاعدة البيانات.

### Phase 3: API
- إنشاء REST endpoints للبحث والمقاطع والمصادر والمراجعة.
- جعل كل الاستجابات JSON واضحة مع رسائل خطأ.
- دعم إنشاء البحث وتحريره وحذفه وتحديثه.

### Phase 4: Internal Research Pipeline
- استخدام وحدات `backend/agents/*` الموجودة.
- إنشاء `backend/services/research_pipeline.js`.
- تنفيذ تسلسل المراحل:
  1. problem framing
  2. source planning
  3. literature organization
  4. methodology review
  5. evidence review
  6. citation review
  7. academic editing
  8. fact checking
  9. final review
- الاحتفاظ بمنطق محلي محدّد وقابل للاستبدال لاحقاً.
- عدم اختلاق مصادر أو مراجع أو DOI أو أسماء مؤلفين.
- إذا لم توجد بيانات مصدر موثقة، العودة بحالة صريحة: "بحاجة إلى مصدر موثّق".

### Phase 5: Frontend Restructure
- تحسين هيكل ملفات الواجهة إلى `frontend/index.html`, `frontend/css/app.css`, `frontend/js/*.js`.
- الاحتفاظ بالهوية العربية RTL والغلاف الفاخر.
- إزالة أي تفاصيل داخلية من الواجهة العامة.
- تهيئة واجهة لإدارة الأبحاث والمصادر والمراجعة.

### Phase 6: Research Dashboard
- إنشاء لوحة أبحاث، نموذج إنشاء/تعديل، مساحة عمل بحثية بملفات/أقسام، وإدارة مصادر.
- ربط الواجهة بالـ API الحقيقي.
- ضمان استمرار البيانات عبر إعادة التشغيل.

### Phase 7: Real Save/Load
- الاعتماد على SQLite عبر API كطريقة حفظ رئيسية.
- استخدام `localStorage` فقط لتفضيلات واجهة غير حرجة.
- دعم إعادة فتح البحث، التحديث، حذف البحث، وإعادة التحميل بعد تحديث الصفحة.

### Phase 8: Demo Research
- إدخال بحث تجريبي واحد فقط عند عدم وجود أي سجل في قاعدة البيانات.
- تأكيد أنه يظهر داخل "أبحاثي" ويكون قابلاً للفتح والتعديل.

### Phase 9: Local Running
- إعداد المشروع لتشغيل backend باستخدام `npm install` ثم `npm start`.
- خدمة الواجهة من Express على `http://localhost:3000`.

### Phase 10: Quality
- التحقق من سلامة HTML/CSS/JS.
- فحص بدء تشغيل الخادم.
- التحقق من قاعدة SQLite.
- اختبار CRUD للبحث.
- اختبار التشغيل على الهاتف.
- التأكد من عدم وجود أخطاء وحدة التحكم أو مسارات مكسورة.

### Phase 11: Documentation
- تحديث ملف `README.md`.
- إنشاء وثائق:
  - `architecture/BACKEND.md`
  - `architecture/DATABASE.md`
  - `architecture/RESEARCH_PIPELINE.md`
  - `architecture/DEPLOYMENT_NEXT.md`

## النتائج المتوقعة
- تطبيق محلي حقيقي لإدارة الأبحاث.
- قاعدة بيانات SQLite داخل المشروع.
- واجهة عربية واضحة تستند إلى فكرة البحث العلمي الحقيقي.
- بنية قابلة للتوسع لاحقاً إلى مزود خارجي أو نشر ويب.
